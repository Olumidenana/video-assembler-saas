# Anti-Timeout Video Splitter & Assembler

Trim, split and stitch videos in the browser with FFmpeg.wasm. The processing runs on the
user's device, so Vercel's serverless time limits never apply to it. Pro features are sold as a
monthly NGN subscription through Paystack, and Supabase handles accounts and plan status.

## Stack

- Next.js 16 (App Router, TypeScript, Tailwind v4) on Vercel
- `@ffmpeg/ffmpeg` 0.12 with self-hosted cores (`@ffmpeg/core-mt` and `@ffmpeg/core`)
- Supabase (auth + Postgres) via `@supabase/ssr`
- Paystack inline checkout + Plans (subscriptions)

## Getting started

```bash
npm install            # also copies the FFmpeg cores into public/ffmpeg
cp .env.example .env.local
npm run dev
```

Checks: `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`.

## Architecture: cross-origin isolation is scoped to `/editor`

Multi-threaded FFmpeg.wasm needs `SharedArrayBuffer`, and the browser only allows that when the
page is cross-origin isolated (`COOP: same-origin` + `COEP: require-corp`). Those headers also
block third-party scripts and iframes like Paystack's inline popup. So:

| Route        | Isolated | Why                                             |
| ------------ | -------- | ----------------------------------------------- |
| `/editor`    | yes      | Multi-threaded FFmpeg                           |
| `/ffmpeg/*`  | n/a      | Self-hosted cores, served with COEP + CORP      |
| everything else (`/pricing`, `/login`, …) | no | Paystack popup and third-party scripts work |

The headers are set in `next.config.ts`.

**Rule:** navigation into or out of `/editor` must be a full page load. Use
`src/components/hard-link.tsx`, not `next/link` or `router.push`. The browser applies COOP/COEP
per document, so a client-side transition leaves the editor non-isolated. If isolation is still
missing (older Safari, embedded webviews), the editor falls back to the single-threaded core in
`public/ffmpeg/st`.

`public/ffmpeg/` is gitignored and regenerated by `scripts/copy-ffmpeg-core.mjs` on
`postinstall`, `predev` and `prebuild`, so Vercel builds it on every deploy.

## Video engine (`src/lib/video`)

| File          | Role |
| ------------- | ---- |
| `engine.ts`   | Owns the single FFmpeg.wasm worker: picks the MT or ST core, mounts files, queues commands, cancels, and restarts after crashes |
| `commands.ts` | Pure FFmpeg argument builders (re-encode vs stream copy, canvas size, plan caps) |
| `export.ts`   | Stitch-into-one and export-each-segment flows |
| `timeline.ts` | Reducer for the edit list (add, reorder, trim, split, split into N-second parts) |
| `probe.ts`    | Parses `ffprobe` JSON into `MediaInfo` (display size after rotation, codecs, fps) |

Points worth knowing before changing it:

- **Files are never copied into wasm memory.** Each clip is mounted read-only with `WORKERFS`,
  so FFmpeg reads straight from the `File`. Only the output lives in memory.
- **Two export paths.** Clips with identical H.264/AAC parameters that need no downscale are
  joined with the concat demuxer and `-c copy`: instant and lossless. Trimmed segments use this
  path only when the user turns on "Fast cut", because copy-mode cuts snap to keyframes.
  Everything else is re-encoded frame-accurately onto one canvas, with letterboxing, a common fps
  and silent audio added where a clip has none.
- **Thread counts are pinned on purpose.** `@ffmpeg/core-mt` 0.12 crashes ("null function or
  function signature mismatch") when libx264 runs more than 5 threads, and x264's "auto" is 1.5x
  CPU cores. `commands.ts` pins the encoder at 4 threads and caps decoder and filter threads. Don't
  remove these without re-testing multi-threaded exports.
- **Progress** comes from the core's `progress` event. FFmpeg's `time=` stats lines end in `\r`
  and only reach the log when the command exits. A watchdog restarts the worker after 60 s of
  silence.
- **Plan limits** live in `src/lib/plans.ts`. They are enforced in the browser, which is inherent
  to client-side processing. What a paid plan protects is convenience, not secrecy.
